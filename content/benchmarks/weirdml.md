## 评估对象

**能力：** 探索和理解陌生数据、搭出机器学习或数据分析流程、在数据有限、目标没说清、反馈极少的条件下仍拿出像样结果的能力。11 题全部由作者 Håvard Tveit Ihle（挪威国防研究所）手工制作，题型有分类、目标检测、仪器数据处理、多任务打包等。被测的是 Agent；官方榜单一行是一个模型加推理强度，并标出所用 Harness 及版本（Claude Code、Codex CLI、Gemini CLI、Kimi Code、opencode）。

**指标：** 每次提交得到 0 到 1 的有效分。一次运行的题目分 = 0.8 × 「迄今最好成绩」曲线在对数 token 轴上从 50 万到 5000 万 token 的归一化面积 + 0.2 × 最终最好成绩。榜单分是 11 题等权平均。截至 2026-11-18 访问官方页面（成绩数据生成于 2026-11-13），29 个上榜配置中最高是 Claude Fable 5.2（xhigh，Claude Code）的 0.431，95% 区间 0.417 到 0.444；其次 GPT-6 Astra（Codex CLI）的 0.422、GPT-6.1 Sol 的 0.383。

## 任务格式

Agent 在沙箱里拿到数据和一段题目说明，多数题不解释数据是什么。它可以自由探索、训练，然后提交。提交物因题而异：一组预测数字、一个在独立评分沙箱里运行的 Python 脚本，或一个被持续监视的预测文件。除 Ship Detect 外每题最多提交 10 次，只算迄今最好的一次，所以后面的坏提交不会扣分。提交后能看到什么也因题而异：有的给分数，有的只给自己的输出图和一小段打印内容，有的什么都不给。多数题附带可以购买的提示。

**示例（题目未公开，以下为官方披露的任务形态；题目 `Shapes Generalize`）**

- **原始题目：** 未公开。官方页面注明题目内容不得进入训练语料，发给模型的说明原文、数据和评分代码都没有放出；题目介绍页只用出品方自己的话描述了 11 题中的 4 题，下面几条就概括自那里。
- **初始状态：** 一个数组，含 1000 个点云，每个 512 个点，没有标签，也没有说明。
- **要做的：** 为留出的 1000 个测试样本各交一个整数。说明只讲了三件事：答案是每个样本一个整数，指标是准确率，弄清这些整数代表什么也是题目的一部分。
- **对 Agent 隐藏的：** 一共有五类形状（圆、五边形、正方形、星形、三角形），整数按类名的英文字母顺序编号；测试集混了六种做法不同的切片（更稀疏、加噪点、两个形状叠在一起、实心轮廓等），其中一片类别不均衡。
- **反馈：** 每次提交返回准确率，以及提交脚本打印内容的约 1000 个字符。
- **提示：** 提示 1 说明编号规则，代价是此后每次提交的分数乘 0.5；提示 2 给出五个类名并包含提示 1，代价是乘 0.35。
- **判分：** 与隐藏标签比准确率，再按该题的下限 0.2 和上限 1.0 线性换算成 0 到 1。限时 6 小时。

**数据格式：** 题目数据、说明原文和评分代码都没有公开，页面注明不得进入训练语料。官方只在题目介绍页详细描述了 11 题中的 4 题，并公开全部正式运行的成绩数据，主要字段如下。

```
weirdml_v3_results.json
├── scoring_rule   计分参数：token 预算 5000 万、计分起点 50 万、最终成绩权重 0.2
├── tasks          11 题各自的类型、归一化下限和上限、提交次数上限、时限、各提示的折扣
├── suite          15 个配置：6 题只有一个配置，4 题分「可买提示」和「无提示」两个，1 题只有无提示
├── models         各模型的 Harness、推理强度、发布日期、token 单价
└── samples        2334 次运行：每次的题目分、面积项、最终最好成绩、token 和费用、
                   停止原因，以及每次提交的原始分、归一化分、提示折扣、有效分
```

## 评估流程

1. **环境：** 每次运行一个带 GPU 的沙箱；官方只在 Bonanza 一题里写明是 4 核 CPU 加 1 块 GPU，GPU 型号没有写。脚本类提交在另一个评分沙箱里限时运行（Bonanza 120 秒，Telescope Pipeline 1200 秒且只有 CPU）。
2. **执行：** 每题的预算是 5000 万总 token，外加 6 小时或 12 小时的时限。运行在提交次数用完、Agent 自己结束、token 用完或超时时停止。Ship Detect 没有提交动作：评测方在每次模型调用前和运行结束时读一次预测文件，逐版记分，这题改用按费用加权的 200 万 token 预算。
3. **提示：** Agent 有一个 `browse_hints` 工具。调用它会用同一模型、同一上下文开一段旁路对话，在里面看到全部提示和价格，决定留下哪些，然后这段对话被丢弃，只有留下的提示回到主对话。不买就不扣分，每题最多浏览 3 次。
4. **判分：** 全部由脚本和隐藏答案比对。原始指标先按该题的下限和上限线性换算并截断到 0 到 1，再乘以已买提示的折扣，得到有效分。
5. **算分：** 每次运行按「指标」一节的公式算题目分；提前结束的运行，最好成绩一直延续到 5000 万 token，50 万 token 之前取得的成绩带入计分区间。同一配置内各次运行取平均（每个模型每个配置多为 5 次），有提示和无提示两个配置各占该题一半权重，11 题等权平均。只有在全部 15 个配置上都有有效运行的模型才上榜。
